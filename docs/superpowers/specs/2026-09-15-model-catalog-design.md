# 模型目录与成本估算设计方案

## 1. 背景与目标

Sage 当前从端点发现模型后，只保存模型 ID 和能力，模型上下文长度与输入/输出价格缺少统一来源。设置页的 `maxContext` 也是全局固定值，无法随着模型切换可靠调整；使用记录也无法基于模型价格估算成本。

本方案建立统一的模型目录和元数据解析链路，支持：

- 保存常见商业模型及内网开源模型的上下文长度、输入价格、输出价格和技术元数据。
- 在设置页展示当前选中模型的有效信息，并提供独立模型目录页进行完整管理。
- 通过 Ollama、LM Studio/llama.cpp、vLLM、Xinference、LocalAI 等服务的适配器探测内网模型信息。
- 在可联网环境手动从 OpenRouter 或自定义 JSON 获取更新，导出后在无互联网的内网环境导入。
- 所有外部更新先形成版本化审核快照，由管理员逐条选择应用，避免未经确认覆盖本地配置。
- 提供“自动跟随模型”上下文模式和按输入/输出 token 价格估算使用成本。

## 2. 范围与非目标

### 范围

- 后端持久化模型目录、数据源、探测结果、用户覆盖和待审核快照。
- OpenRouter 与自定义 JSON 数据源；数据源接口可扩展。
- 内网文件导出/导入、版本校验、差异审核和冲突处理。
- 统一模型 ID 规范化和元数据生效优先级。
- 设置页当前模型信息展示、自动上下文开关和独立模型目录管理页。
- 输入/输出 token 成本估算。

### 非目标

- 首版不自动定时访问互联网；同步由用户手动触发。
- 首版不实现缓存命中/写入价格或阶梯价格计算，但数据结构预留扩展点。
- 不承诺从所有 OpenAI-compatible 服务的 `/v1/models` 响应获取完整元数据；只使用服务明确提供的信息。
- 不根据模型名称猜测价格或上下文长度。
- 不把“模型原生上下文上限”直接等同于服务启动时配置的实际上下文限制。

## 3. 核心概念与数据模型

### 3.1 模型目录记录

每个逻辑模型以规范化的 `canonicalModelId` 聚合多个来源，同时保留来源模型 ID。建议字段：

- `id`：目录记录唯一 ID。
- `canonicalModelId`：用于跨数据源匹配的规范化 ID。
- `provider`、`modelId`、`displayName`：提供商、原始模型 ID 和展示名称。
- `nativeContextWindow`：模型原生声明的最大上下文长度，未知时为空。
- `serviceContextWindow`：特定端点探测到的实际服务限制，未知时为空。
- `inputPricePerMillion`、`outputPricePerMillion`：每 1M token 价格；本地模型默认 0，可由用户填写内部折算价。
- `currency`、`pricingUnit`：首版默认 USD 和 `per_1m_tokens`。
- `capabilities`、`architecture`、`quantization`：能力、架构和量化信息。
- `source`、`sourceVersion`、`sourceUpdatedAt`：数据来源和更新时间。
- `metadata`：不影响核心计算的扩展字段。
- `userOverrides`：按字段保存用户覆盖值及编辑时间，不与来源值混淆。
- `createdAt`、`updatedAt`：目录记录生命周期字段。

价格字段使用可空数值区分“免费/明确为 0”和“未知”；成本估算遇到未知价格时返回“无法估算”及缺失字段，不默认为 0。

### 3.2 端点探测记录

探测结果必须与目录基线分离，至少包括：端点 ID、模型 ID、协议/适配器类型、服务实际上下文、探测到的技术元数据、探测时间、成功或失败状态及错误摘要。探测失败不得删除既有目录数据。

### 3.3 审核快照

每次联网同步或自定义 JSON 导入都创建不可直接生效的快照：

- 快照 ID、格式版本、来源类型、来源标识、生成时间、内容 SHA-256。
- 快照中的模型记录和规范化结果。
- 与当前生效目录逐条比较后的状态：`new`、`updated`、`conflict`、`unchanged`。
- 字段级旧值、新值、差异和建议操作。
- 每条记录的审核状态：待审核、应用、忽略；审核人和审核时间。

## 4. 生效值解析规则

### 4.1 字段级优先级

对每个字段独立解析，不使用整条记录覆盖：

```text
用户手工覆盖
  > 内网服务实际探测值
  > 导入的同步目录
  > Sage 内置目录
  > 未知
```

用户手工覆盖始终最高。服务探测只覆盖它明确探测到的字段；探测不到时回退到同步目录和内置目录。用户价格覆盖不会被服务上下文探测结果改变。

### 4.2 模型匹配

匹配顺序为精确端点/提供商与模型 ID、规范化 ID、别名映射。规范化只能处理明确的提供商前缀和版本表示，不通过模糊相似度自动合并可能不同的量化或微调模型；无法确定时创建独立记录并标记待审核。

量化模型保留独立的原始模型 ID、量化信息和端点探测限制。只有在来源明确声明继承关系时，才可展示基础模型的目录上下文；不能因为量化名称相似就覆盖实际探测值。

## 5. 数据源与内网同步

### 5.1 可插拔数据源接口

定义统一数据源接口，输入同步选项，输出 Sage 内部候选模型记录和来源元数据。首版实现：

1. **OpenRouter 适配器**：手动请求公开模型目录，映射上下文和输入/输出价格。
2. **Custom JSON 适配器**：校验版本化 JSON 文件，将其转换为同一候选记录格式。

网络请求仅在用户明确触发时执行，超时、HTTP 错误和字段缺失以可见错误返回，不生成部分成功的生效数据。OpenRouter 响应只产生待审核快照。

### 5.2 导出与导入

导出文件包含格式版本、生成时间、来源、记录列表、可选审核状态和 SHA-256。联网环境可导出候选快照或已审核目录；内网只需通过文件导入即可，不依赖外部 API。

导入步骤：验证 JSON schema、格式版本、校验值和字段范围；保存为待审核快照；计算逐条字段差异；由管理员逐条应用、忽略或应用并保留本地字段。导入不得自动覆盖用户覆盖字段。

## 6. 服务探测适配层

统一适配器接口按端点协议和服务类型执行模型信息探测：

- Ollama：优先读取本地模型详情中的上下文和量化信息。
- LM Studio/llama.cpp：读取可用模型详情；必要时解析用户可访问的 GGUF 元数据。
- vLLM、Xinference、LocalAI：读取其模型/运行时信息接口；若只返回模型 ID，则只更新可确认的字段。
- 通用 OpenAI-compatible：只消费响应中明确存在且通过 schema 校验的元数据。

探测结果带端点和时间维度，服务实际上下文只对对应端点生效。对于模型文件声明值与服务启动配置冲突，服务实际探测值用于当前请求限制，模型原生值仍保留用于展示和目录参考。

## 7. 上下文配置与请求链路

在模型设置中增加“自动跟随模型”开关：

- 开启时，模型切换后使用当前模型的有效上下文值更新请求预算；未知时保持安全默认值并提示上下文未知。
- 关闭时，使用用户固定的 `maxContext`，目录信息仍可展示并用于成本估算。
- 请求层最终计算安全值：不超过模型原生上限、当前端点服务实际限制和用户/自动模式请求上限中已知的最小值。
- 保留用户固定值和自动解析值，切换模式不会丢失用户设置。
- 现有设置迁移为默认关闭或依据现有行为选择兼容默认值；迁移必须不改变既有用户的固定 `maxContext`。

## 8. 成本估算

成本计算器接收模型生效价格和一次请求的输入、输出 token 数：

```text
inputCost  = inputTokens  / 1_000_000 * inputPricePerMillion
outputCost = outputTokens / 1_000_000 * outputPricePerMillion
totalCost  = inputCost + outputCost
```

结果包含输入成本、输出成本、总成本、货币、使用的价格来源和估算状态。未知价格返回缺失字段，不静默当作免费。缓存价格和阶梯价格通过可选价格结构预留，但不在首版参与计算。

## 9. 前端界面

### 设置 → 模型

在当前选中模型旁展示：有效上下文、输入/输出价格、来源、更新时间和探测状态。增加自动跟随模型开关，以及自动值与用户固定值的区分。当前模型没有元数据时显示未知，不阻塞手动配置。

### 独立模型目录页

提供搜索、按提供商/来源/能力过滤、详情编辑、新增模型、用户覆盖字段、探测结果、快照列表、逐条差异审核、导入/导出和手动同步。审核页面必须同时显示旧值、新值、来源和受用户覆盖保护的字段。

## 10. 后端接口与持久化边界

后端提供模型目录 CRUD、当前有效值查询、探测触发、快照导入/导出、快照差异查询和逐条审核接口。接口响应采用项目现有的设置/API 约定，并对外部 JSON 做 schema 校验。

目录、快照和探测结果使用项目现有持久化抽象；具体表名和迁移方式在实现计划中根据当前数据库层确定。内置目录作为版本化只读种子数据，不直接与用户记录混写。

## 11. 错误处理与安全

- OpenRouter API key 只从端点/安全配置读取，绝不进入导出快照或日志。
- 导出的模型目录不包含 API key、Authorization header 或完整请求响应。
- 导入文件限制大小、记录数量和数值范围，拒绝未知危险结构及重复主键。
- 网络错误、schema 错误、校验失败和审核冲突均保留可追踪状态，不静默回退为免费或 4096。
- 价格使用十进制定点或等价的无损表示，避免浮点累积误差影响账单估算。

## 12. 测试策略

- 单元测试：ID 规范化、字段级优先级、用户覆盖保护、价格计算、未知值处理、快照差异分类、JSON 校验和导入导出校验。
- 集成测试：目录 CRUD、快照审核事务、探测适配器、设置迁移、请求层上下文上限合并。
- 前端组件测试：设置页信息展示、自动模式切换、目录搜索编辑、逐条审核和冲突提示。
- 端到端测试：联网环境拉取并导出、内网模拟导入审核、选模型后自动上下文生效、成本估算展示。
- 覆盖率目标遵循项目最低 80%，并为 Ollama、OpenAI-compatible 和至少一个 vLLM 类适配器保留协议回归用例。

## 13. 风险与后续演进

- 外部目录的模型 ID、价格和上下文可能过期，因此所有更新必须审核并显示来源时间。
- 不同服务对上下文的实际含义不同，必须保留模型原生值与服务运行值两个维度。
- GGUF 元数据不保证等于服务实际限制，文件解析只能作为来源之一。
- OpenRouter 价格是公开目录价格，不代表用户自建服务的内部成本；本地模型价格必须允许独立覆盖。
- 后续可增加 LiteLLM、自建目录、缓存价格、阶梯价格和定时同步，但不改变首版快照审核和字段级优先级。
