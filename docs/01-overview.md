## 1.1 项目背景

### 1.1.1 问题陈述

当前 Windows 7 用户面临以下困境：

1. **现代 AI 工具断供**
   - Chatbox 要求 Node.js ≥20.0.0，Electron 32+
   - Hermes Agent 基于 Python 3.10+，无桌面客户端
   - 主流 AI 助手均已放弃 Win7 支持

2. **轻量级需求被忽视**
   - Win7 机器通常配置较低
   - Electron 应用内存占用 150MB+
   - 需要更轻量的解决方案

3. **记忆与进化能力缺失**
   - 现有桌面 AI 助手多为单次对话
   - 无跨会话记忆能力
   - 无法从交互中学习和进化

### 1.1.2 目标用户

| 用户画像         | 需求                           |
| ---------------- | ------------------------------ |
| Win7 怀旧用户    | 继续使用熟悉系统的轻度 AI 助手 |
| 低配置电脑用户   | 需要轻量级 AI 工具             |
| 记忆型助手需求者 | 希望 AI 记住偏好和上下文       |
| 开发者/极客      | 喜欢可定制、可扩展的 AI 工具   |

## 1.2 项目定位

### 1.2.1 产品定义

**Sage** 是一款本地优先的记忆型 AI 桌面助手：以持久记忆与人类在环的自演化为核心，以 Office 全链路写作代理为差异化能力，主线覆盖 Win10+/macOS/Linux，并通过 LTS 分支长期维护 Windows 7 SP1。

### 1.2.2 核心价值

| 价值       | 说明                               |
| ---------- | ---------------------------------- |
| **记忆型** | 跨会话记住用户偏好、习惯、重要信息 |
| **进化型** | 从交互中学习，不断优化响应质量     |
| **本地型** | 数据全部本地存储，支持离线 / 内网部署，Win7 LTS 分支持续维护 |
| **可扩展** | 支持技能插件和自定义配置           |
| **交付型** | Office 文档按格式规范生成、校验、修复，直接可交付 |

### 1.2.3 Slogan

> **"Sage - 你的记忆型 AI 助手"**

## 1.4 技术选型

### 1.4.1 核心技术栈

| 层级        | 技术选型      | 版本                     | 说明                                   |
| ----------- | ------------- | ------------------------ | -------------------------------------- |
| 桌面框架    | Electron      | 21.4.4                   | main 与 win7 LTS 同版本；main 后续可升级 |
| 前端框架    | React         | 18.x                     | FSD 分层                               |
| 前端构建    | Vite          | 5.x                      | 快速构建                               |
| 后端语言    | Python        | 3.11+（main）/ 3.8（LTS） | FastAPI，六边形架构                    |
| 数据库      | SQLite        | 3.x                      | 零依赖                                 |
| 向量存储    | ChromaDB      | 0.4.x                    | 轻量向量 DB                            |
| AI SDK      | openai-python | 1.x                      | OpenAI 兼容端点统一接口                |
| HTTP 客户端 | httpx         | 0.25.x                   | 异步支持                               |
| ORM         | SQLAlchemy    | 2.x                      | 数据库抽象                             |

### 1.4.2 技术选型理由

**为什么最初选择 Tauri、后来迁回 Electron？**（历史决策，详见 `archive/tech-docs-2026-06-13/`）

| 对比项    | Electron        | Tauri 1.x           |
| --------- | --------------- | ------------------- |
| 内核      | Chromium (独立) | WebView2 (系统内置) |
| Win7 支持 | 已终止          | 支持 (需 KB4549949) |
| 内存占用  | ~150MB+         | ~20MB               |
| 安装包    | ~100MB+         | ~10MB               |
| Node 要求 | ≥20.0.0         | 无 (Rust 后端)      |

Tauri 1.x 在 Win7 + Rust 工具链上的依赖图过于脆弱（见 `.gitignore` 中 Cargo.lock 注释），且 WebView2 在 Win7 上的可用性依赖系统补丁；2026-06 决定统一回 Electron 21.4.4（最后一个支持 Win7 的大版本），以 LTS 分支冻结方式承担 Win7 兼容，主线不再受 Win7 约束。

**为什么选择 Python 后端？**

1. **灵活性** - 快速迭代，易于调试
2. **生态丰富** - AI 库、工具库完善
3. **学习成本低** - 用户可自行扩展
4. **跨平台** - Linux/Mac 也能运行

**为什么选择 ChromaDB？**

1. **轻量** - 单文件，易部署
2. **本地优先** - 无需云服务
3. **向量检索** - 支持语义记忆
4. **Python 原生** - 与后端无缝集成

## 1.5 约束与限制

### 1.5.1 平台约束

| 约束     | 说明               |
| -------- | ------------------ |
| 最低系统 | main：Windows 10 / macOS / Linux；LTS：Windows 7 SP1 x64 |
| 运行时   | Electron 21.4.4 内置 Chromium；LTS 需 KB3033929（SHA-2 签名） |
| 网络     | 支持 TLS 1.2       |

### 1.5.2 性能约束

| 约束     | 目标                  |
| -------- | --------------------- |
| 内存占用 | < 200MB (空闲 < 80MB) |
| 启动时间 | < 3 秒                |
| 响应延迟 | < 5 秒 (不计 AI 延迟) |

### 1.5.3 数据约束

| 约束     | 说明               |
| -------- | ------------------ |
| 本地存储 | 所有数据存储在本地 |
| 隐私优先 | 不上传用户数据     |
| 可导出   | 支持数据导出       |
