# 工具调用显示优化

**日期**: 2026-08-01  
**状态**: 已完成  
**PR**: 待创建

## 问题描述

用户在 Sage 中询问"查看代码并给出优化建议"时遇到两个 UI 问题：

1. **工具调用顺序错误**: 读取文件的工具调用显示在优化建议之后，而不是之前。实际流程是先读取文件，再给出建议，但 UI 显示顺序相反。

2. **文件内容显示冗余**: 读取文件时，完整的文件内容直接显示在会话区的工具调用部分，占用大量空间，影响观感。

## 根因分析

在 `src/widgets/chat/Message.tsx` 中：
- 工具调用渲染位于消息内容之后（第 336-412 行）
- 工具结果 `tc.result` 直接内联显示，无截断或折叠机制

## 解决方案

### 1. 重新排序渲染结构

将工具调用渲染移到消息内容之前，符合 ReAct 模式的实际执行顺序：
```
ThinkingPanel (思考过程)
↓
Knowledge references (知识引用)
↓
File attachments (文件附件)
↓
Tool calls (工具调用) ← 移到此处
↓
Message content (消息内容)
↓
Bottom info (底部信息)
```

### 2. 可折叠的大文件内容

新增 `ToolCallResult` 组件：
- 阈值：300 字符
- 小于阈值：直接显示
- 大于阈值：显示折叠按钮 + 字符计数，点击展开后在 `<pre>` 标签中显示完整内容
- 使用 `Eye` / `EyeOff` 图标切换展开状态

## 修改文件

- `src/widgets/chat/Message.tsx`
  - 添加 `Eye`, `EyeOff` 图标导入
  - 新增 `ToolCallResult` 组件（第 118-145 行）
  - 重新排序：工具调用渲染移到消息内容之前（第 225-262 行）
  - 删除旧的重复工具调用渲染代码

## 用户体验改进

### Before
```
[消息内容 - 最终优化建议]
[工具调用 - 读取文件]
  └─ 完整文件内容（可能上千字符）
```

### After
```
[工具调用 - 读取文件]
  └─ 展开 (1234 字符) ▶  (折叠状态)
[消息内容 - 最终优化建议]
```

点击"展开"后：
```
[工具调用 - 读取文件]
  └─ 收起 ▲
     └─ [pre 标签显示完整文件内容，max-h-80 overflow-y-auto]
[消息内容 - 最终优化建议]
```

## 技术要点

1. **ReAct 模式对齐**: 工具调用先于最终回答，符合 LLM 的实际执行流程
2. **渐进式披露**: 大文件内容默认折叠，用户需要时手动展开
3. **性能优化**: 避免渲染大量 DOM 节点，减少初始渲染成本
4. **向后兼容**: 小结果（<300 字符）仍直接显示，无交互负担

## 后续优化建议

- 考虑为不同类型的工具结果定制折叠策略（如代码文件 vs 命令输出）
- 可以为特定工具（如 `read_file`）添加语法高亮的预览
- 考虑添加"复制到剪贴板"按钮便于查看大文件内容
