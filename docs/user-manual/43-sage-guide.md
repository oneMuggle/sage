# Sage 向导（🧭）

> 内置不可删除的官方向导：解答 Sage 用法、引导排障、按需修改 Sage 配置。

## 1. Sage 向导能做什么

| 能力 | 例子 |
|---|---|
| **解答** | "重试次数默认多少？""工作区外写入怎么配？""权限档位有几个？" |
| **指导** | "为什么我这边后端 401？""sage doctor 报 X 怎么修？" |
| **改参数** | "帮我把重试次数改成 10""把思考档位默认调到 detail" |

向导基于 Sage 内置文档（用户手册 + 精选技术章节）回答，并能在回答时给出引用出处（"见用户手册 §XX.X"）。

## 2. 如何使用

向导**默认启用**，安装后直接出现在左侧专家列表第一位，头像 🧭，名字"Sage 向导"。点击卡片即可开始对话。

向导右上角显示"内置"徽章，不允许删除 —— 即使你不小心在数据库或配置中尝试删除，也会被拒绝（400 错误 `protected_agent`）。

## 3. 改参数的五步法

向导修改 Sage 配置时遵循严格的五步工作流，**不得跳步**：

1. **读当前值**：调 `read_sage_config` 看现在设的是什么
2. **说明影响**：告诉您这个改动会影响什么、有什么副作用
3. **请求确认**：明确问您"是否确认修改？"
4. **写新值**：经您同意后调 `update_sage_config`
5. **回读校验**：再调一次 `read_sage_config` 确认改动确实生效，并向您报告结果

这个流程确保您不会被"偷偷改配置"，且每一步都可回溯。

## 4. 向导不会做的事

向导**只有**配置与诊断工具，**不会**：

- ❌ 写工作区文件
- ❌ 执行 shell 命令
- ❌ 安装依赖
- ❌ 操作数据库
- ❌ 做通用编程 / 写作 / 调研

如需这些能力，请切换到对应的专家（编码 / 写作 / 研究）。

## 5. 权限边界

向导声明的权限上限是 `workspace_write`，即便您全局权限设成 `full_access`，向导本身也只能使用配置类工具，不能写任意文件。

修改配置的 `update_sage_config` 工具属于"自管理工具"，**每次调用都必须您明确确认** —— 即便您之前连续批准了 10 次，第 11 次仍会弹确认框。这是为了防止配置被批量自动改动。

## 6. 敏感信息

向导遵循严格的信息脱敏规则：

- **API Key / Token / 密码一律不展示**：问"我的 API key 是什么"只会回答"已设置 / 未设置"，不回显实际值
- **不知道的配置键就说不知道**：不编造键名（`update_sage_config` 有白名单校验，编造也会被拒绝）

## 7. 常见问题

**Q: 向导的回答不准确怎么办？**
A: 向导基于仓库文档回答，文档未覆盖的部分会明确告知"没覆盖"。如发现回答与文档不符，请通过"帮助 → 反馈问题"上报。

**Q: 能不能让向导回答通用问题？**
A: 不建议。通用问题请用主助手或对应专家，向导的 prompt 与工具集都针对 Sage 自身，混用会降低回答质量。

**Q: 我可以删除向导吗？**
A: 不可以。向导是 Sage 的内置组件，被设计为不可删除，以保证任何时候都能获得 Sage 自身的官方答案。

**Q: 文档里有些内容过时了怎么办？**
A: 向导只能基于当前仓库里的文档回答。如发现过时内容，请通过"帮助 → 反馈问题"上报或直接修改仓库文档（PR 合入后下次启动即生效）。

**Q: 为什么向导说"内置文档中未找到相关内容"？**
A: 该问题可能不在当前文档覆盖范围内。建议：

- 改用 `sage_self_status` / `sage_doctor` 看实时状态
- 在主助手会话中直接问，由通用 LLM 回答
- 通过反馈渠道让文档团队补充
