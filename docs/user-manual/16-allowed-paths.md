# 17 — 额外访问路径（Allowed Paths）与工作区边界

## 工作区边界规则一览

Sage 按「读」和「写」两条线执行不同的边界策略：

| 操作 | 当前工作区内 | 工作区外 |
|------|--------------|----------|
| **读取**（`read_file`、`office_read`、`office_read_pdf`、`office_analyze` 等） | 直接执行 | **直接执行，无需审批**（与 `read_file` 一致） |
| **写入**（`write_file`、`office_create`、`office_update`、模板填充、PDF 生成等） | 直接执行 | 命中 `allowed_paths` 自动放行；未命中弹出审批对话框 |
| **@-mention 附件**（消息中 `@文件名`） | 自动读取 | 命中 `allowed_paths` 自动读取；未命中跳过并说明原因 |

换句话说：**读不设围栏，写才需要边界控制**。`allowed_paths` 的作用是减少工作区外写入
和 @-mention 的反复审批，而不是限制读取。

## 什么是 Allowed Paths？

Allowed Paths 是项目级配置的额外路径规则。命中规则的路径视为"项目信任路径"：

- 写入工作区外的文件时**自动放行**，不弹确认框
- 消息中 @-mention 的工作区外文档**会自动读取**为附件
- 未命中规则的工作区外写入仍会弹出审批框

典型场景：

- 让 agent 直接把报告写到 `~/Documents/`
- 让 agent 修改 `~/Desktop/` 上的现有文档
- 让 agent 读取共享目录中的参考资料（读取本身无需配置，但配置后 @-mention 也能生效）

## 新建项目时的默认预填

为了减少首次使用时的审批打扰，新建项目会自动预填以下规则（仅加入实际存在的目录）：

| 平台 | 默认规则 |
|------|----------|
| 全平台 | `~/Documents/**`、`~/Desktop/**`、`~/Downloads/**` |
| Windows | 额外加入 `D:/Documents/**`、`E:/Documents/**`（如存在） |

重新打开或登记已存在的项目**不会重置**这些规则——你在创建向导或项目设置中的修改会保留。

## 如何添加/编辑 Allowed Path

1. 打开左侧栏的 **项目设置**（齿轮图标）
2. 找到 **额外访问路径** 区域
3. 点击 **+ 添加路径**
4. 输入路径规则（支持通配符）
5. 点击 **保存**

### 路径规则格式

| 规则 | 含义 | 示例 |
|------|------|------|
| `~/Documents/**` | Documents 及所有子文件 | 常用参考资料目录 |
| `~/Desktop/*.pdf` | 桌面所有 PDF | 临时查看 PDF |
| `/tmp/scratch/*` | scratch 直接子文件 | 临时数据 |
| `~/projects/shared` | 整个目录 | 共享项目目录 |

**提示：**

- `~` 代表你的 home 目录（如 `/home/user` 或 `C:\Users\YourName`）
- `**` 匹配所有层级子目录
- `*` 只匹配当前层级
- 相对路径规则相对于项目根目录展开

## 首次写入未授权路径

当 agent 试图**写入**既不在 workspace 也不在 `allowed_paths` 中的文件时，会弹出审批对话框：

```
🔐 访问授权请求

工具: office_create
Agent 想写入: /home/user/Desktop/报告.docx

[拒绝]  [允许]  [项目级允许]
```

三个选项：

- **拒绝** — 本次拒绝，agent 无法写入
- **允许** — 本次允许，下次还会询问
- **项目级允许** — 将该路径加入 allowed_paths，以后不再询问

审批通过只对当前这次工具调用生效；想长期放行请选择「项目级允许」或手动编辑规则。

## 注意事项

1. **读写不对称**：读取工作区外文件不需要审批；只有写入需要。
2. **审批粒度**：单次「允许」只放行本次调用；「项目级允许」写入项目 `allowed_paths`。
3. **持久化**：allowed_paths 保存在项目设置中，跨会话生效。
4. **跨平台**：路径规则在 Windows/macOS/Linux 上都能正常工作。
5. **安全**：未命中的写入路径仍会被拦截并等待用户确认；路径解析会消除 `..` 与符号链接逃逸。
