# 23 — 全局规则

> 面向最终用户的操作指南。开发者视角（API 契约 / 安全模型 / 原子写）见
> [102-global-rules.md](../technical/102-global-rules.md)。

---

## 1. 这个功能做什么

Sage 每次对话都会把一份「全局规则」塞进 system prompt 的最上层。
你在这里写的内容，**对所有工作区、所有会话生效** —— 适合放"我是谁、
我习惯什么、永远不要做什么"这类跨项目通用的要求。

入口：**设置 → 工具与连接 → 全局规则**。

文件落在 `~/.sage/SAGE.md`（Windows 上是 `C:\Users\<你>\.sage\SAGE.md`）。
以前只能手动建这个文件，现在可以在设置页里直接编辑。

---

## 2. 界面说明

| 区域 | 内容 |
| --- | --- |
| 状态行 | 文件路径 / 大小 / 最后修改时间 / 是否被截断 / 是否符号链接 |
| 编辑框 | 全文编辑区，等宽字体，支持多行 |
| 计数行 | 当前字符数 + 是否超出预算 + 是否有未保存修改 |
| 按钮 | 撤销（回到已保存内容）/ 删除 / 保存 |
| 起步模板 | 三个一键追加的片段（中文输出规范 / 代码风格 / 安全规范） |

---

## 3. 常见操作

### 3.1 第一次写全局规则

1. 打开 **设置 → 工具与连接 → 全局规则**
2. 点一个模板（例如「中文输出规范」）把常用片段填进编辑框
3. 在模板基础上补充你自己的要求
4. 点 **保存**

保存成功后状态行右侧会显示「已保存 HH:MM:SS」，3 秒后自动消失。

### 3.2 修改已有内容

编辑框里改，保存按钮点亮即可点。改错了点 **撤销** 回到上次保存的内容。

### 3.3 删除

点 **删除** 会移除 `~/.sage/SAGE.md` 这个文件（`~/.sage` 目录保留）。
删除后下次对话就不再注入全局规则。

> 删除后会**立刻**生效于下一次对话；已经进行中的对话不受影响。

### 3.4 不小心删了想恢复

全局规则没有版本历史。删除操作一旦执行，内容就没了 ——
建议在删除前先把内容复制到别处。

## 4. 字符预算与截断

Sage 注入全局规则时**只取前 8000 个字符**。

- 编辑框下方的计数会实时显示当前字符数
- 超过 8000 会显示黄色「超出预算」提示，但**仍然可以保存**
- 状态行出现「已截断」标记时，说明文件实际内容超过了 8000 字符，
  超出部分不会被注入 —— 精简掉不必要的内容即可

保存本身的硬上限是 64KB（64 × 1024 字节），超过会被拒绝。

---

## 5. 安全扫描

保存时会做一次内容检查，拦截两类东西：

- **看起来像提示注入的字面量**：`<|system|>`、`[INST]`、
  "ignore previous instructions" 之类
- **密钥形状的字符串**：看起来像 API Key / token 的长串

被拦截时会显示具体原因，改掉对应内容再保存即可。

> 这条扫描是**防手滑**的护栏，不是安全边界 —— 它只认字面量形状，
> 拦不住语义级的恶意内容。真正保护你的是文件系统权限：
> `~/.sage/SAGE.md` 只有你自己这个系统账号能写。

---

## 6. 符号链接

如果 `~/.sage/SAGE.md` 是一个指向别处的符号链接：

- **读取**：会正常读取链接指向的内容，状态行显示黄色「符号链接」标记
- **保存**：会**拒绝**并提示"目标文件是符号链接，拒绝写入"

这是为了防止误把 `~/.ssh/id_rsa` 之类的重要文件当成规则文件覆写掉。
如果确实想用符号链接，请先把它换成普通文件（或改掉链接）。

---

## 7. 和项目级规则的关系

| 层级 | 文件 | 生效范围 | 优先级 |
| --- | --- | --- | --- |
| 全局 | `~/.sage/SAGE.md`（本页） | 所有工作区 | 低 |
| 目录 | 任意目录下的 `SAGE.md` / `CLAUDE.md` | 该目录及其子目录 | 中 |
| 项目 | 项目设置里的 description / instructions | 该项目 | 高 |

冲突时**更具体的一层覆盖更笼统的一层**。所以全局规则里适合写通用偏好，
具体项目的要求放进项目设置或项目目录里的 `SAGE.md`。

## 8. 常见问题

**Q：改完要重启 Sage 吗？**
不用。下一次发起对话时就会读取新内容。

**Q：为什么状态行显示"读取失败"？**
通常是没有读权限或者文件不是 UTF-8 编码。检查一下文件权限，
或者把内容另存为 UTF-8 再试。

**Q：能写多条规则吗？**
可以。建议用 Markdown 的标题和列表组织，例如：

```markdown
# 输出语言
- 始终使用简体中文回答

# 代码风格
- 函数不超过 50 行
- 优先早返回
```

**Q：保存了但 AI 好像没按规则做？**
先看状态行有没有「已截断」标记 —— 规则可能被截在 8000 字符之后。
另外规则是"软约束"，模型可能因为任务本身的要求忽略它；
把最关键的几条写在文件**最前面**效果更好。
