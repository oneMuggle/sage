# 项目上下文（description / instructions / 资料 / 保存回答）

> 让 Sage"记住"每个项目的目标、约定和参考资料。下次打开该项目时,
> 这些信息会自动注入到 AI 的工作上下文中,不用每次重复粘贴。

---

## 这是什么

在 Sage 里,你可以为每个项目维护一份"项目记忆":

- **项目说明 (description)**:这个项目是做什么的、用什么技术栈、有什么约束
- **项目指令 (instructions)**:希望 Sage 在这个项目里遵守的写作/编码风格
  (例如"用中文回答"、"回复保持简洁"、"代码示例必须可运行")
- **项目资料 (materials)**:你希望 Sage 看到的参考资料 — Wiki 摘录、过往
  设计文档、典型问答片段等 Markdown 文本

下次在该项目下开新会话或继续聊天时,Sage 会自动把上述内容拼到提示词中,
AI 会"知道"这个项目的上下文,无需你重复说明。

---

## 在哪里设置

在 **侧边栏 → 项目** 区域(展开某个项目后)可以看到两个面板:

### 1. 项目概览(顶部)

- **项目说明** 文本框:简短描述这个项目,例如「公司内部 Wiki 工具,Python
  3.10 + FastAPI + SQLite,主要面向 HR 团队」
- **项目指令** 文本框:给 AI 的指令,例如「用中文回复」「回答保持简洁」

填写后点击「保存」(文字变灰即保存中,绿色提示已保存)。

> **生效时机**:保存后,该项目下的下一次新消息自动应用。老消息不受影响。

### 2. 项目资料(底部)

管理该项目的"参考资料库"。

#### 添加资料(三种方式)

- **粘贴文本**:在顶部"添加资料"文本框粘贴 Markdown 文本,点「添加」
- **保存当前回答**:当前会话中如果 Sage 给了好答案,点「保存当前回答」
  即可把最后一条 AI 回答存为资料,下次开新会话还能引用
- **重复内容自动合并**:同一条资料多次添加,系统按内容哈希去重,
  不会产生重复行

#### 资料状态徽章

| 状态 | 含义 | 操作建议 |
|---|---|---|
| 待索引 (黄) | 刚添加,后台还在索引中 | 等待几秒后自动转「已索引」 |
| 已索引 (绿) | 正常可用,Sage 会在相关问题上引用 | 无需操作 |
| 索引失败 (红) | 内容过大或格式异常 | 删除后重新添加,或联系支持 |

#### 单条大小

- 单条资料最多 **64 KB**(约 3-5 万汉字)
- 超出会被拒绝(返回 413 错误),需要拆分

#### 删除资料

每条资料右侧的「删除」按钮会立即移除该资料 — Sage 的下一次回复
**不会**再引用它,但该资料的历史引用记录(如它出现在已发送的回答中)
保持不变。

## 优先级与边界(可选阅读)

Sage 把所有上下文按优先级注入(从高到低):

1. **应用安全规则** — 不可被任何上下文覆盖
2. **项目指令 (instructions)** — 来自当前项目的 instructions
3. **SAGE.md / CLAUDE.md** — 来自项目目录的约定文件(由 Sage 自动发现)
4. **全局风格偏好** — 在设置里配置的全局偏好
5. **项目资料 (materials)** — 用户添加的参考,**仅作为额外上下文,不得覆盖上方指令**

这条优先级链在系统提示词中显式声明,所以模型知道"资料"是参考、
"指令"是必须遵守的,避免资料里的命令式语句覆盖项目指令。

## 典型场景

### 场景 A:跨会话保留上下文

今天用 Sage 帮你分析了某段代码,你想明天继续:
1. 在项目资料里点「保存当前回答」
2. 关掉 Sage,明天再打开
3. 新会话开始时,这段回答自动出现在 AI 视野里,可被引用、可被追问

### 场景 B:把 Wiki 文章作为长期参考

你写了一份项目设计 Wiki,想让 Sage 在所有后续问答中考虑它:
1. 把 Wiki 内容(或关键摘录)粘贴到「添加资料」
2. Sage 在回答时会标注参考了哪条资料(看回答中的 "(来源消息 xxx)" 标识)

### 场景 C:项目说明保持一致

多个同事共用同一台 Sage、同一项目目录:
1. 一次性写好 description + instructions 并保存
2. 所有人在该项目下都看到相同的指令,不需要每次口头约定

## 常见问题

**Q: 资料内容超过 64 KB 怎么办?**
A: 拆分成多条添加,或只放关键摘要。Sage 注入时每条单独截到 8 KB,
超出预算的资料会被排除并在底部标注"另有 N 条资料超出预算被排除"。

**Q: 我添加的资料 AI 没引用,是不是坏了?**
A: 资料是"被动上下文",Sage 只在判断相关时才引用,与 Wiki 主动检索
不同。如果你希望 AI 必读某条资料,把它放到「项目指令」(instructions)
里用更强语气写明。

**Q: 删除资料后,之前引用过它的回答会变吗?**
A: 不会。已经发出的回答不会重新生成,内容固定。删除只影响未来的回复。

**Q: 「保存当前回答」为什么有时按钮是灰的?**
A: 当前会话还没收到 AI 回答,或者没有活跃会话绑定到该项目。
切换到该项目下,等 Sage 回复一条消息后再点。

**Q: 项目之间资料会串吗?**
A: 不会。每个项目的资料严格按项目 ID 隔离,默认不跨项目共享。

## 数据存储与隐私

- 项目说明/指令/资料存于本机 SQLite(`sage.db`),不上传云端
- 删除资料是硬删除,无回收站
- 资料 SHA-256 内容哈希用于幂等去重,本身不暴露给模型
- 资料内容会被注入到 LLM 提示词,如果你使用云端 LLM 服务商,
  该服务商可能在他们的日志中看到资料内容(由你的上游 LLM 配置决定)
