## 1. 任务中心在哪

任务中心提供**三个入口**，信息密度递增：

| 入口 | 位置 | 看到什么 |
|---|---|---|
| **rail 徽章** | 左侧导航栏「任务」图标 | 红点 = 有活跃任务（queued / running / paused / awaiting_approval）或失败任务 |
| **侧边栏分区** | 点击 rail「任务」图标展开 | 折叠卡，每组最多 3 条任务 |
| **完整页面** | 地址栏 `#/tasks` | 六源全量、筛选、详情深链 |

> 旧版本（alpha.78 之前）的右下角浮动胶囊已删除，所有任务管理统一走侧边栏。

---

## 2. 六种任务来源

任务中心聚合六类来源，每一类都从原有页面收集过来，无需再跳转：

| 来源 | 代表什么 | 例子 |
|---|---|---|
| **registry** | 工具调用触发的后台任务 | bash 长命令、文件处理、shell 脚本 |
| **chat** | 当前会话外的其他 AI 对话 | 多会话并行时，其他窗口的 AI 任务 |
| **lane** | 编排泳道（多 Agent 协作） | `lanes` 编排的规划-执行-审校流水线 |
| **goal** | 闲时自主目标 | "每天自动整理笔记"、"周末生成周报" |
| **todo** | 待办事项 | 手动创建的 todo 清单 |
| **scheduled** | 定时任务 | 一次性 / 周期性定时执行的 AI 任务 |

> 每个任务卡左上角的**来源徽章**标识它属于哪一类。

## 3. 任务操作

**取消正在运行的任务**：任务卡右上角 × 按钮 → 立即取消。页面任务（shell）/ 后台会话 / 编排 / 闲时目标支持取消；待办（todo）与定时任务（scheduled）不支持取消（× 按钮不显示）。

**重试失败任务**：

| 来源 | 重试方式 |
|---|---|
| goal / scheduled / todo | 在对应页面（`/goals` / `/scheduled` / `/todos`）重新触发 |
| registry / chat / lane | 任务卡显示"错误详情"，根据提示修复后重新发起 |

**查看详情**：点击任务卡 → 深链到对应页面（`/goals/:id`、`/orchestration` 等）。shell 类任务直接弹出 shell 输出抽屉，不跳页。

## 4. 系统通知

当**闲时目标**（goal）完成或失败时，Sage 会发 OS 系统通知：

- **完成通知**：「目标 XXX 已完成」
- **失败通知**：「目标 XXX 失败：[原因]」

通知在 Sage 桌面端运行时才会发出。如果你关闭了桌面端，下次启动时不再补发（任务状态可在 `/goals` 页面查看）。

> 定时任务、待办提醒、后台 Bash 任务也发 OS 通知（与闲时目标走同一条 `collectNotificationItems` 链路）。仅 chat 与 lane 不发 OS 通知——它们在各自页面（`/chat` / `/orchestration`）内有内联状态。

## 5. 常见问题

**任务突然不见了**
- 终态（succeeded / failed / cancelled）的任务只在本次会话保留。重启 Sage 后不再显示，但目标/待办/定时任务的历史仍在各自页面（`/goals` / `/todos` / `/scheduled`）。

**侧边栏没看到任务分区**
- 当前没有任何运行中或待处理的任务时，分区会自动隐藏。发起一个任务后就会出现。

**rail 徽章不显示红点**
- 红点只在「活跃任务（queued / running / paused / awaiting_approval）」或「失败任务」存在时出现。所有任务都成功完成 → 红点消失（正常行为）。

**闲时目标完成但没收到系统通知**
- 确认桌面端正在运行（不是 Web 版本）。
- 检查系统通知权限：macOS 在「系统设置 → 通知 → Sage」；Windows 在「设置 → 系统 → 通知」。

**任务卡显示「等待审批」**
- 来源是编排泳道（lane）的任务在等待你确认下一步。点击任务卡查看详情并处理。
