# 51 — 项目健康与 AI 规程助手

> 2026-11-14 新增：项目健康看板、主动告警、AI 对话式规程定制
> 2026-11-15 看板界面改版：三张指标卡、按状态分组、逾期徽标

## 项目健康看板

### 查看方式

打开「项目」页面，健康看板显示在顶部搜索栏下方、项目列表上方，会自动检查所有**活跃**项目（一次最多 100 个）。

### 三张指标卡

看板顶部并排三张指标卡，从左到右依次是 **风险 / 关注 / 正常**：

| 指标卡 | 颜色与图标 | 数字含义 |
|---|---|---|
| 风险 | 玫红 + 警示三角 | 被判为「风险」的项目个数 |
| 关注 | 琥珀 + 感叹号圆圈 | 被判为「关注」的项目个数 |
| 正常 | 翠绿 + 绿色对勾 | 状态正常的项目个数 |

卡片上的数字是**项目个数**，不是里程碑个数。切换下方的筛选按钮时，三张卡的数字不会变化，始终反映全部活跃项目的整体情况。

### 状态怎么判定

- 🔴 **风险**：有里程碑逾期 **7 天及以上**（以最久的那条为准）
- 🟡 **关注**：有里程碑逾期 1~6 天，**或**有里程碑处于阻塞状态
- 🟢 **正常**：没有逾期，也没有阻塞

「关注」不一定意味着逾期——里程碑卡住（阻塞）但还没到期时，同样会被判为关注。

### 项目列表

项目列表按状态分组，顺序固定为 **风险 → 关注 → 正常**，没有项目的分组不会出现。

- 当筛选为「全部」、且同时有多个状态的项目时，每个分组前会有一行小标题（状态圆点 + 组名 + 该项目数）。
- 只筛选某一个状态时，列表不再分组，直接平铺。

每条项目占一行，从左到右依次是：状态圆点、项目名称、阶段标签（项目设置过阶段时才显示）、「已完成/总数 里程碑」，最右侧是逾期徽标或状态文字。

### 逾期徽标

项目只要有未完成的逾期里程碑，该行右侧就会出现玫红色的圆角徽标 **「逾期 N 项」**，N 是逾期的里程碑条数。徽标固定为红色，与项目本身是风险还是关注无关。

没有逾期时，行尾改为显示文字状态：存在风险 / 需要关注 / 一切正常。

### 筛选与刷新

- 顶部的 **全部 / 风险 / 关注 / 正常** 胶囊按钮可以按状态筛选，当前选中的按钮高亮。
- 筛选后没有任何项目时，会提示「没有符合该风险等级的项目。」
- 点击 **重新检查** 会立即重新扫描所有活跃项目并更新状态；检查期间按钮显示「检查中…」，首次打开看板时列表位置会先出现几行灰色占位。
- 如果检查失败，看板里会显示「健康检查失败：…」以及错误原因。

### 看到结果后怎么处理

- **风险**：优先处理逾期最久的里程碑；可进入项目治理页查看具体是哪几条逾期。
- **关注**：确认逾期的里程碑能否尽快补齐；如果只是阻塞，先解除阻塞。
- **正常**：无需处理，继续推进即可。

### 单项目健康卡

进入任一项目的「治理」页 → 「项目概览」分区，会显示该项目的健康卡片：

- 卡片按状态变色（风险玫红 / 关注琥珀 / 正常翠绿），标题右侧显示状态词
- 显示里程碑进度条，标出已完成/总数与完成百分比
- 有逾期时，最多列出 3 条逾期里程碑，每条右侧标注「逾期 N 天」；超过 3 条会追加「…还有 N 项」
- 仅因阻塞而被关注时，提示「有 N 个里程碑处于阻塞状态」
- 状态正常时提示「所有里程碑进度正常」

## 主动告警

当检测到项目存在逾期或风险时，桌面端会弹出通知：

- **通知标题**：「项目风险提醒」
- **通知内容**：包含逾期天数与项目名称
- **节流策略**：同一项目、同一严重度每 24 小时只推送一次，避免打扰

## AI 规程助手

### 启用

在项目工作台 → 「规程」面板 → 点击 **AI 定制**。

### 对话流程

1. **启动**：点击「开始对话」，AI 会根据项目目录与内置模板生成规程草案
2. **多轮对话**：在输入框中描述需求，例如：
   - 「加一个中期检查阶段」
   - 「把实施阶段拆成数据采集和数据分析两个阶段」
   - 「结题阶段需要增加经费决算产物」
3. **回退**：如果调整不满意，点击「撤销上一步」回到上一版规程
4. **确认绑定**：规程满意后，点击「确认绑定」生效

> 提示：对话最多支持 10 轮。超过轮次会强制要求确认当前版本。

### 未配置 LLM 时

若后端未配置 LLM 端点，AI 助手会降级为基于规则的草案生成：

- 输入「中期检查」→ 自动在规程中插入中期检查阶段
- 输入「延期」→ 调整后续阶段的时间节点
- 输入「结题」→ 追加结题阶段

降级草案会弹出提示：「（未配置 LLM，已降级为规则草案）」。

### 从项目目录推断

若希望 AI 根据已有文件自动推断阶段划分：

1. 点击 **从目录推断** 按钮
2. 助手会扫描项目目录，识别类似 `01_开题`、`02_实施` 的编号目录
3. 显示推断结果（含置信度与来源）
4. **需要手动点击「绑定推断结果」** 才会生效——推断结果不会自动覆盖已有规程

### 从 Git 历史推断

同样通过「从目录推断」按钮，助手会同时分析最近的 git 提交记录：

- 匹配「开题报告」「初稿」「实验数据」「结题」等关键词
- 按提交时间分桶，推断项目经历的阶段
- 合并目录与 git 两种来源的结果

## 常见问题

**问：定时健康检查什么时候运行？**
答：每天上午 09:00 自动扫描所有活跃项目，生成健康报告并触发桌面通知。

**问：AI 规程助手会覆盖我已绑定的规程吗？**
答：不会。AI 助手生成的是草案，必须手动点击「确认绑定」才会生效。

**问：为什么 AI 助手提示「降级为规则草案」？**
答：后端未配置 LLM 端点（例如未安装 OpenAI / 未设置 API key）。此时使用规则引擎生成基础草案，不影响功能使用。

**问：定时检查会影响性能吗？**
答：不会。定时任务在 Electron 启动后注册，由 `SchedulerService` 调度，仅在每天 09:00 触发一次。扫描过程限制最多 100 个项目，超时即中止。
