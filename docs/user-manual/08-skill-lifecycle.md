# 08. 技能生命周期（Skills Lifecycle）

> **最后更新**：2026-08-30
> **用户入口**：顶级 **技能** 页面（路由 `/skills`）

## 8.1 这是什么

Sage 中的技能由内置技能或 `SKILL.md` 文件描述。生命周期状态用于区分技能近期是否使用过，以及用户是否将其归档。归档是可逆的软标记，不会删除磁盘上的 `SKILL.md` 文件。

## 8.2 三种生命周期状态

| 状态 | 含义 | 页面显示 |
|---|---|---|
| **active（活跃）** | 最近一次使用在默认阈值内 | 活跃 |
| **stale（已冷）** | 超过默认阈值未使用，或从未使用 | 已冷 |
| **archived（已归档）** | 用户主动归档 | 已归档 |

默认阈值为 **30 天**。当前实现是在读取技能列表时根据使用记录即时计算 `active` / `stale`；没有独立的 24 小时后台扫描任务，也没有 `curator.json` 配置文件。

## 8.3 如何打开技能页面

从侧边栏选择 **技能**，或直接打开 `/skills`。技能是顶级导航入口，不在设置页内。命令面板也可以打开同一路由。

技能卡会显示来源（`builtin` 或 `skillmd`）、版本（若有）、使用次数和生命周期徽章。`SKILL.md` 技能还可以展开查看提示词正文及其来源目录。

## 8.4 归档和取消归档

### 8.4.1 归档

在技能卡上点击 **归档**。归档请求通过：

```text
POST /api/v1/skills/{name}/archive
```

请求体为：

```json
{"archived": true}
```

归档后：

- 技能卡显示“已归档”；
- 生命周期元数据持久化到 SQLite；
- `SKILL.md` 文件及其目录内容保持不变；
- 归档状态不会因为重启 Sage 而丢失。

### 8.4.2 取消归档

在已归档技能卡上点击 **取消归档**，使用同一路由并传入：

```json
{"archived": false}
```

取消归档后，技能会依据当前使用记录显示为 `active` 或 `stale`，而不是无条件恢复为 `active`。

## 8.5 归档与删除的区别

| 操作 | 是否修改 `SKILL.md` 文件 | 是否保留技能 | 是否可恢复 |
|---|---:|---:|---:|
| **归档** | 否 | 是 | 是 |
| **删除** | 是，删除技能目录 | 否 | 否（除非另有备份） |

删除只适用于 `source=skillmd` 的用户技能，内置技能不能删除。删除使用：

```text
POST /api/v1/skills/{name}/delete
```

## 8.6 数据存放位置

| 数据 | 实际位置或来源 |
|---|---|
| 内置技能 | `backend/skills/builtin/` |
| 用户技能发现根 | `$SAGE_SKILLS_DIR`、项目目录 `./skills`、用户目录 `~/.sage/skills`（按优先级） |
| 用户技能文件 | 发现根下的 `<name>/SKILL.md`；也支持发现根下的单文件 `SKILL.md` |
| 生命周期元数据 | SQLite 的 `skill_lifecycle` 表（`archived`、`archived_at`） |
| 使用统计 | SQLite 的 `skill_usage` 表 |

实际发现根由后端 `discover_skill_md_dirs()` 根据环境变量、当前工作目录和用户目录决定，不应假定所有安装都使用同一个绝对路径。

## 8.7 故障排查

| 现象 | 处理 |
|---|---|
| 侧边栏看不到“技能” | 确认当前应用加载的是包含 `/skills` 顶级导航的版本；也可直接打开 `/skills`。该入口不依赖渐进式解锁。 |
| 状态一直显示“已冷” | `stale` 包含从未使用的技能；检查技能是否实际执行过，以及后端是否能读取 `skill_usage`。 |
| 归档后重启又恢复 | 检查后端使用的 SQLite 数据库是否发生切换或不可写；归档写入失败只记录 warning，不应阻塞技能主流程。 |
| 归档后文件不见了 | 归档不会删除文件；若文件确实消失，请检查是否执行了“删除”或被外部文件管理操作移除。 |
| 归档按钮不见了 | 确认技能列表项来自当前支持生命周期操作的版本；内置技能的其他管理操作仍受其来源限制。 |
