# 网页访问与登录态

> Sage 的网页搜索 / 网页抓取 / 文件下载能力，以及登录态（Cookie）的管理：凭据面板、自动刷新、浏览器健康与出网指标。

## 能力总览

Sage 的 agent 有三条出网通道，按需自动选择：

| 通道 | 用途 | 说明 |
| --- | --- | --- |
| 静态抓取 | 普通网页 / API | httpx 直连，带重试与限速 |
| JS 渲染 | SPA / 动态页面 | 无头 Chrome 渲染，命中 JS 壳或反爬时自动升级 |
| 交互浏览器 | 登录 / 复杂操作 | 真实 Chrome 窗口，支持点击 / 输入 / 截图 |

所有通道共享同一份**登录态（Cookie / header 凭据）**：在浏览器里登录一次，导出后静态抓取与 JS 渲染都能带上。

## 设置 → 网络

### 网站凭据

- **列表**：显示已保存的凭据（域名 / 类型 / Cookie 名 / 剩余时效），**永不显示凭据内容**。
- **删除**：点删除按钮并二次确认。删除后相关站点的抓取会回到未登录状态。
- **新增 header 凭据**：填域名（如 `.api.example.com`）、头名（如 `Authorization`）、头值（如 `Bearer xxx`）后保存。适合 API key / Bearer token 类站点。
- 值全部加密存储（Windows DPAPI / macOS keychain / Linux secret-tool）；平台加密不可用时列表会标"明文"，请尽快处理。

### 登录态怎么来

1. 对话里让 agent 打开浏览器（`browser_launch`，可要求 `headless=false` 弹出真实窗口）；
2. 你在窗口里手动登录目标站点；
3. 让 agent 执行 `browser_cookies` 导出——凭据进入档案，三条通道立即可用。

### 登录态自动刷新

设置 → 网络 → 凭据区块的"登录态自动刷新"开关（默认关）。开启后：带凭据的请求被踢到登录页时，Sage 会用当初导出凭据的持久浏览器 profile 静默重访一次、重新导出 Cookie 并重放请求——大多数情况下你不需要手动重新登录。

### JS 渲染使用持久 profile

"JS 渲染使用持久 profile"开关（默认关）。开启后渲染通道使用独立持久 profile，登录后的 SPA 页面直接可读（渲染与静态通道共用登录态）。

## 浏览器健康

凭据区块顶部显示 Sage 实际使用的浏览器与版本。出现黄色警告时：

- **未发现浏览器**：安装 Chrome / Edge，或设置 `SAGE_BROWSER_PATH` 环境变量指向浏览器路径；
- **版本较旧**（Chrome < 120，常见于 Win7 的 109）：部分站点可能拒绝访问，建议升级或指定新内核。

## 出网指标

凭据区块下方的"出网指标（本进程内）"按域名显示最近的成功 / 失败 / 升级渲染次数与平均耗时，附"刷新 / 重置"按钮。指标为进程内存态，重启清零。

## 常见错误与出路

| 错误 | 含义 | 出路 |
| --- | --- | --- |
| `http_403/429/503` | 站点反爬拦截 | 已自动尝试真浏览器重放；仍失败请配置代理或换源 |
| `credential_expired` | 凭据全部过期 | 重新登录后 `browser_cookies` 导出；或开启自动刷新 |
| `login_required` | 登录墙（凭据失效） | 同上；开启自动刷新可自愈 |
| `html_instead_of_file` | 期望下载文件却拿到登录页 | 携带凭据重试，或走浏览器通道 |
| `forbidden_origin` | 非 Sage 页面发起的请求被拒 | 正常防护，无需处理 |

## 浏览器剪藏扩展

剪藏扩展跑在你自己的浏览器里，天然继承真实登录态，与上述 Cookie 桥互相独立。
