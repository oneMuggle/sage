# 网页访问 Round 30：渲染内容完整度可观测（2026-09-24）

- **上游文档**：Round 2（wait_for R2）；Round 22-27 渲染链既有成果
- **范围**：后端 only（web_render.py + test_web_render.py）

## 0. 结论速览

`wait_for`（R2）允许调用方指定"等到某选择器出现"，但命中与否**不可见**：
半截内容与完整内容在工具输出上无法区分，模型只能靠正文长度猜测。R30 让
`wait_page_ready` 返回命中布尔，`render_page` 在指定 wait_for 时于结果中
暴露 `wait_for_satisfied`——内容完整度首次成为一等信号。

## 设计

1. `wait_page_ready` 返回 `bool`：
   - 未指定 wait_for → 恒 True；
   - 指定时 = 轮询窗口内选择器是否出现；**settle 循环对所有路径照常执行**
     （回归防护：首版实现把 settle 提前 return 掉，被既有 settle 测试当场
     拦下——语义是"命中标志"而非"提前返回"）；
   - `BrowserCDPError`（上下文销毁）在 readyState 阶段按 True（页面没了，
     无内容可言）、在 selector 阶段按 False；
2. `render_page`：`wait_for` 非空时结果带 `"wait_for_satisfied": bool`；
   经 web_tool 的 `content.update` 自动透出，前端/模型无需新契约；
3. `browser_navigate` / AU3 `refresh_credentials` 忽略返回值，行为不变。

## 测试

- wait_page_ready：命中 True / 窗口耗尽 False / 未指定 True；
- render_page：命中 True / 未命中 False（`wait_for_satisfied` 键）。
