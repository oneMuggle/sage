# R107 Agent 工具白名单未发布插件条目标注与就地移除规格

- 日期：2026-10-26
- 基线：`main` `5108b26f55b96670208137ce53e2613563badb15`
- 状态：已合并（PR #2545）
- 编号说明：R107 为 `plugin-evo-index.md` 的插件账轮次号，
  与其它账本的同号计划无关。
- 前置：R92 起 Agent 工具白名单是自由文本（精确名 +
  两个受限通配），R94 起另有运行中插件工具复选框。
  条目本身一直可见，但用户无从判断某条 `plugin__…`
  还对什么生效：插件停运/卸载/从未存在时条目在后端
  fail-closed 静默不命中，表单里却与在效条目一模一
  样。这正是 R101 为已保存权限规则补过的「孤儿可
  见化」，在 profile 白名单一侧从未做。本轮与 R103
  同为纯前端补齐：前端已有发布快照 `runtimeTools()`
  与生命周期名单 `list()` 两处权威数据，不需要新后
  端面。

## 1. 目标与语义

- EditAgentForm 新增「未发布的插件条目」区（仅非
  空时出现）：逐条列出白名单中当前不对任何已发布
  工具生效的插件形条目，标注三类原因——**插件已
  卸载**（生命周期 status=uninstalled）、**插件无
  记录**（生命周期名单查无归属）、**当前未发布**
  （插件在册但该工具/该插件眼下没有发布到聊天）；
  每条可就地「移除」，只改白名单草稿、仍需点保存
  （与复选框取消勾选同一性质）。
- 分类是只读派生、永不落盘：归属判定与后端 R101
  同口径——遍历生命周期权威插件名（长名优先消
  歧），构造候选通配/命名空间后结构化比对，绝不切
  分条目字符串猜插件名；`plugin__*` 全局通配与非
  插件形条目永不标注；与发布快照精确同名、或等于
  某已发布插件派生通配的条目算在效，不标注。
- 降级口径与 R101 一致：生命周期名单读不到 → 整
  体不标注（不把「读不到」误报成「无记录」）；运
  行快照加载中/失败 → 只给已卸载/无记录两类，
  「当前未发布」不猜。

## 2. 边界

- 纯前端：不新增后端端点/Electron 命令（manifest
  仍 269），不改 profile 存储形状（`tools` 仍是
  原字符串数组），不动后端 allowlist 匹配语义。
- 移除只是表单草稿编辑：不自动保存、不联动卸
  载/启停插件；卸载插件仍不自动清任何配置（既定
  边界）。
- 不做批量移除（白名单是用户自有配置，逐条人工
  决定）；不标注内置工具名；不做跨 Agent 汇总。
- EditAgentForm 全文件为中文硬编码文案（无 i18n
  框架），新文案随宿主惯例硬编码，措辞对齐 R101
  徽标。Win7 按既有口径待对齐（本轮无后端新代
  码）。

## 3. 实现要点

- `EditAgentForm.tsx` 新增导出纯函数
  `findStalePluginToolEntries(entries, publishedTools|null, pluginRecords|null)`：
  形状判定逐条镜像 `backend/domain/tool_names.py`
  （字符集、`is_plugin_tool_name`、受限通配解
  析），归属镜像 `_rule_plugin_owner`（权威名长名
  优先、派生通配全等或命名空间归属）。
- 与既有 `runtimeTools()` 同一刷新周期并行取
  `pluginClient.list()`（刷新按钮一并更新）；失败
  置 null 走降级，不新增错误 UI（发布快照已有失
  败提示，生命周期读不到时标注区整体缺席）。
- 面板挂在运行中插件工具面板之后（同一工具字段
  块内），`data-testid="agent-stale-plugin-entries"`；
  逐行等宽条目 + 原因徽标 + 移除按钮；移除经
  `setToolsText`/`onChange` 走既有草稿管线。
