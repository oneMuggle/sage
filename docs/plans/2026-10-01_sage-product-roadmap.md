## 1. 目标和原则

默认产品承诺：本地优先、记忆增强、能按要求交稿的 AI 工作台。按可信底座、完整成果流程、持续复用三个批次推进。

- 在上述独立工作树工作，不修改主 checkout、其他会话 worktree 或其未提交现场。
- 本方案先落盘，业务修改随后进行。每批均给出实际改动、回归结果和未完成项，不把“有设计”当成“已交付”。
- 优先复用现有项目 API、ContextMeter 来源清单、Office 模板/预览/校验/交付、任务中心、技能和定时任务。
- 不以旧评审缺失清单覆盖较新代码，不重复建设来源面板、快照等已存在基础。
- UI 保持 calm、dense、operational；不做装饰性全站换皮。
- 不引入付费测试调用，不修改真实用户数据库；测试使用 mock 与临时数据库。
- 不自动推送、合并或发布，不绕过本机审批。远端新鲜度和 CI 结果单独记录。

## 2. 基线复核

两个新工作树已创建且初始干净。相对于上一轮评审快照，主线已有 UX-IA R2 D 的相关性裁剪、路径预算和技能来源；Win7 有 R2 C 的预算截断来源说明，后续不重复做一套上下文预算系统。

当前读取的关键问题仍需处理：

1. 文本项目资料添加仍写 pending_index，上下文只取 ready。已有独立修复提交可借鉴，但本轮不覆盖其原工作树。
2. 普通 settings IPC 失败被吞掉；关键入口需要严格写入回执。聊天权限入口已有失败恢复，可复用其语义。
3. Ollama 首启支持无密钥，而侧栏的统一状态判定仍不一致。
4. 临时聊天只控制长期记忆；sessionStorage 会在重启时丢失。采用非破坏性的“暂停长期记忆”契约，不伪装成无历史/离线模式。
5. 设置默认 general 与可见导航不一致，且有具体项搜索但缺定位。
6. 任务中心已有状态聚合；终态和待验收应准确呈现，不再新建任务状态引擎。
7. 首页仍以通用代码/搜索/脑暴为主，项目管理仍主要在侧栏，Office 生成主要是字段/模板入口。

## 3. 批次 A：可信底座与快修

### A1 项目资料可用性

- 文本资料创建成功即可以作为上下文使用；ready 表示可用，不宣称向量索引已经完成。
- 复核既有修复，并对旧 pending 文本资料提供明确、限定范围的兼容修复策略。
- 不把失败项、真实索引任务或其他项目资料无条件变为成功。
- 更新状态文案和单测，覆盖新增、幂等添加、旧记录、删除及项目范围。

### A2 严格保存与真实回执

- 保留旧客户端的兼容读/写入口，同时增加/复用严格写入通道。
- 失败不得派发成功变化事件。
- 首启保存必须等待严格回执，不在 Promise 尚未完成时显示成功。
- 权限、快照、预算等关键控件显示保存失败并恢复可确认值；连续操作不得由旧失败覆盖新成功。
- 缓存不能冒充后端已保存；缓存不可用与后端保存失败应分开处理。

### A3 协议感知的接入状态

- 配置完整性和连接测试使用同一端点协议规则。
- Ollama 不要求 API Key；其他协议维持既有密钥要求。
- 传递协议，保护迟到请求不覆盖当前端点状态。
- 不静默发起真实计费推理测试。

### A4 长期记忆契约

- UI 名称明确为暂停/不使用长期记忆，而不是承诺不保存历史的临时会话。
- 以会话为单位在当前设备持久保存选择，兼容旧的 sessionStorage 标记。
- 存储失败可见，不谎称已持久保存。
- 服务端请求值限制为合法模式，仍兼容旧客户端缺省值；现有 off 请求继续跳过记忆注入/提取。
- 明示：历史、文件和产物照常保留；云端模型仍收到本轮请求。此设备设置不冒充跨客户端全局策略。
- 不实施自动删除历史，不运行真实数据迁移命令。

### A5 设置与任务状态快修

- 设置初始落点 basic；非法/旧 key 有可测试的回退规则。
- 终态不使用持续运行的动画；分清实际运行、待授权、待验收、失败与完成。
- 复用现有元数据和后端状态，不以组件 isLoading 重新定义任务事实。

## 4. 批次 B：成果导向 UI 与办公主旅程

### B1 成果首页与首个成功任务

- 默认场景：写报告、整理资料、分析表格、制作演示；编码仍保留专业入口。
- 点击打开具体任务简报，而不是只有空 prompt 前缀。
- 简报包含受众、目标、资料、交付类型、长度/格式要求、项目范围。
- 提交进入现有聊天/写作执行链路，不新增绕过权限的文件生成通道。
- GitHub 指向项目仓库；不可用的固定端口 WebUI 不伪装成正常任务入口。

### B2 项目工作台

- 新建项目工作台入口；侧栏负责选择，工作台提供足够空间管理项目目标、指令、资料、会话和成果。
- 优先复用 ProjectSection / 项目类型与 API，新增展示模式或提取邻近组件，不复制项目存储。
- 明确项目与工作目录/授权范围的区别，不自动扩大 allowed_paths。
- 目录可选/虚拟项目是独立数据模型议题，不与首个工作台强绑。

### B3 设置和聊天层级

- 默认按基础、模型、记忆资料、工具安全、网络远程、诊断用量组织导航。
- 旧 tab 和专业设置继续可发现；兼容映射保留。
- 搜索项可定位/高亮，不再只切页。
- 保证模型、安全状态和发送/停止可达，其余详情按需展开；不移除现有快捷键、折叠、push/overlay 能力。

### B4 文档交付闭环

- 任务简报 → 资料范围 → 大纲/计划 → 草稿 → 预览修订 → 检查 → 验收导出 → 版本保留。
- 复用 OfficeGenerateForm、模板、编辑预览、检查、快照与交付抽屉。
- 独立表达文件生成、格式检查、来源核验、可编辑性与验收状态，不把调用成功等同于可交稿。
- 四格式使用各自检查能力；本机转换器缺失时明确降级，不生成假预览/假检查。

## 5. 批次 C：可追溯与持续复用

### C1 上下文/来源可检查

- 基于现有 ContextMeter 来源和预算元数据，强化“实际使用 / 被截断 / 被排除 / 未验证”的呈现。
- 对网页、Wiki、项目资料、文件、长期记忆保留真实来源，支持已有的来源跳转。
- 不显示完整隐藏推理链，不把模型自述当事实审计。
- 不新增不一致的 source 真相来源；Win7 仅回灌可以在 Py3.8 验证的改动。

### C2 任务配方与复用

- 将任务简报/成熟流程保存为可复用配方，保留项目范围、输出约定和检查要求。
- 区分草稿与用户/交付链路已验收状态；未经验收不宣称已验证。
- 连接已有模板/技能/定时任务入口，执行前明确参数、权限、时间和预算。
- 不自动运行保存的任务；不在后台静默创建定时操作。
- 对重复提交/重试验证不会造成重复副作用。

### C3 能力感知模型与预算

- 复用现有模型目录、会话覆盖、fallback、每日花费控制。
- 推荐/路由考虑工具、视觉、结构化输出和上下文能力；未知能力明确显示未知。
- 跨模型/服务商切换有明确结果和数据范围，不能静默降级到不具备必要能力的模型。
- 预算区分估算、实耗和未知价格；需要硬限额时由后端执行并验证，不能仅用 prompt 或客户端标签冒充限额。
- 不引入新模型依赖或新增计费服务；没有可验证接口的能力继续标待实施，不生成假按钮。

## 6. 双轨兼容与边界

不修改架构基线来掩盖新增违规，不增加外部依赖，不在已有超大文件堆积新逻辑；必要时提取邻近助手/组件，保持原有公共入口。

## 7. 验证策略

每批采用最小回归、相关现有测试、类型/结构门禁逐层扩展：

1. 后端资料仓库、请求模式及上下文相关单测，数据库为 fixture/临时库。
2. 前端严格回执、首启、端点、记忆持久化、设置与任务状态测试。
3. 首页简报、项目路由、资料、交付及配方交互测试，使用 mock API。
4. TypeScript renderer 与 Electron typecheck。
5. 架构检查、相关 lint、格式检查；不把 pytest wrapper 的“未安装而跳过”当成功。
6. Win7 运行 Py3.8 真实解释器的相关后端测试，不仅做语法猜测。
7. 记录 1024×768、大字号、深浅色、英文与键盘路径的验收范围；未实际运行的视觉验证明确列未验证。
8. CI 是最终门禁；没有推送/CI 结果就不宣称 CI 通过。

测试命令使用明确 cwd 和已定位解释器。长任务保留 command_id，以实际退出码为准；仅查看/停止本会话启动的命令。
