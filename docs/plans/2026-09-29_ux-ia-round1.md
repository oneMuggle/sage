## 1. UI 优化

### 1.1 信息架构：从“功能菜单”改为“工作区”

| 现状 | 主流做法 | 建议 |
| --- | --- | --- |
| 一级导航 对话/记忆/知识库/设置 + 更多（Office/技能/智能体/编排/Arena/帮助） | ChatGPT、Claude：左栏只有 新对话 / 搜索 / 项目 / 历史；其余进头像菜单 | 左栏只保留 **新对话、搜索（⌘K）、项目、历史会话** 四块。记忆、技能、智能体、MCP 统一收进“自定义”页（相当于 ChatGPT 的 Customize / GPTs），设置和帮助放到左下角头像菜单 |
| 侧栏有 6 个可折叠分组，各自设 maxHeight（50vh/30vh） | 同一时间只滚动一个列表 | 会话和项目合并成一棵树：项目 → 会话，未归属的会话放在“最近”里。待办、定时、Git 移到右侧面板的标签页，不再占用左栏 |
| Office 是独立页面 | Claude Artifacts / ChatGPT Canvas：文档在对话右侧打开 | Office 文档默认在对话右侧的 **Canvas 面板**里预览和修订；独立的 Office 页降级为“文档库” |
| Welcome 页（127 行）比较单薄 | ChatGPT、Gemini：居中大输入框 + 场景卡 + 最近项目 | 新会话页 = 居中输入框 + 项目选择器 + 3～4 张场景卡（写论文 / 改报告 / 分析表格 / 整理笔记），场景卡直接预填 FormatSpec 模板 |

### 1.2 对话区

- **Composer 工具条化**：参考 ChatGPT 的“+”菜单和 Claude 的工具开关，把附件、@ 引用、技能、MCP 工具、联网、权限模式放进输入框左侧的一个“+”弹层。模型选择器和上下文用量（`ContextMeter`）放右侧。现在这些组件（`PermissionModeSwitch`、`SessionModelPicker`、`KnowledgeChip` 等）散落在头部和输入区。
- **工具调用分组折叠**：DESIGN.md §11 已经规定折叠态 ≤40px。建议进一步参考 Claude Code / Cursor，把连续的多个工具调用合成一行“已执行 7 步 · 读 3 个文件 · 改 2 处”，点开才展开时间线。长任务的消息列表会清爽很多。
- **状态横幅合并**：`CompactBanner`、`TopicShiftBanner`、`InterruptedRunBanner`、`TruncationNotice`、`ContextPressureBadge` 最多可能同时出现 5 种。建议统一成一条“会话状态条”，按优先级只显示一条，其余收进“ⓘ”弹层。
- **记忆写入透明化**：参考 ChatGPT 的“记忆已更新”提示，`MemoryWriteHints` 改成消息下方的小徽标，点开可以撤销或编辑。这正契合 PHILOSOPHY 里“透明可控”的原则。

### 1.3 视觉与设计系统

- DESIGN.md 已经很规范。建议加 **lint 级守卫**：在 eslint 里禁用 `text-white/*`、`border-black/*`、非 4 倍数的间距、同一组件超过 2 种图标尺寸，让规范可以自动检查。
- 主按钮现在是 `bg-ui-bg + border`，和次要按钮区分度偏低。建议引入一个**强调色 token**（`--color-primary`），只用于主 CTA、选中态和焦点环。Claude（陶土色）和 ChatGPT（黑白）都靠一个强调色来建立识别度。
- 补齐**空状态、加载骨架、错误态**三件套组件，统一放在 `shared/ui`，每个页面必须用。
- 可访问性：焦点环、`aria-live` 播报流式输出完成、键盘能走完主要流程（新建 → 输入 → 发送 → 审批 → 查看 diff）。

## 3. 逻辑 / 架构优化

### 3.1 前端

- **拆分巨型模块**：`useChat.ts` 按职责拆成 `useStreamTransport`（SSE/重连）、`useMessageStore`（消息状态）、`useRunControl`（中断/重试/继续生成）、`useToolApprovals`。`Chat.tsx` 只做布局编排，目标是每个文件 ≤400 行。这样也能直接减少双分支 cherry-pick 冲突。
- **单一状态源**：服务端数据统一走 `@tanstack/react-query`，本地 UI 状态放 `store`，禁止在组件里另存一份服务端数据副本。流式消息用“事件 → reducer”模型，便于回放和测试。
- **流式渲染性能**：消息列表已经用了 `react-virtual` 和尾窗。建议再加上：流式 token 按 `requestAnimationFrame` 合批 setState；Shiki、Mermaid 放进 Web Worker，或在视口外延迟高亮。

### 3.2 后端

- **收编 `legacy_routes.py`**（2359 行）：按六边形架构把 chat 主链路迁到 `application/chat_service` + `api/chat_routes`。system prompt 组装（M3/M6/L5 各段）抽成可单测的 `PromptAssembler` 管道，每段声明预算和优先级，替代现在的全量拼接。
- **上下文预算统一**：项目资料、SAGE.md、记忆召回、技能清单共用一个 token 预算器。超出时按相关性检索或截断，而不是整条排除。还要给用户展示“本轮注入了哪些上下文”（相当于 Claude 的 context 可视化）。
- **运行时可观测**：每一轮对话生成 trace（模型调用、工具调用、耗时、token），在右侧面板提供“运行详情”视图。`trajectory-pane` 分支可以作为基础。

### 3.3 双分支工程

- 本地 worktree 已经超过 70 个，许多已合并或上游已删除（如 `analysis/round26` 显示 `gone`）。建议定期执行 `git worktree prune`，并用脚本清理已合并分支，降低误操作风险。
- main 和 win7 的差异建议集中到**适配层**（Python 3.8 兼容 shim、Electron API 差异），业务代码保持一份。可以配合 CI 的“兼容性 lint”（禁用 3.10+ 语法等），让 cherry-pick 从人工对齐变成自动化。
