# 网页访问 Round 33：事件驱动就绪等待（2026-09-24）

- **上游文档**：web-access 总账 §3 P3 首项；Round 22/R23 事件通道基建
- **范围**：后端 only（browser_events.py / web_render.py + test_browser_events.py）

## 0. 结论速览

`wait_page_ready` 以 0.3s 粒度轮询 readyState，load 早已完成的页面平均白等
0.15-0.3s。R33 在事件通道上补 Page 事件路由：attach 时 `Page.enable`，
`Page.loadEventFired` 按 sessionId 置信号；render_page **导航前布防**
（attach 先于导航，事件不会漏），导航后优先等事件——就绪即进入 settle，
事件缺失/超时回落 readyState 轮询，行为只会更好不会更坏。

## 设计

1. `_EventChannel` 增 `_page_loads`（session_id → Event）+ `_dispatch`
   路由 `Page.loadEventFired`；`attach_network` 加发 `Page.enable`；
2. 模块接口：`arm_page_load(browser_id, session_id)`（导航前布防）/
   `wait_page_load(browser_id, session_id, timeout)`（等信号，一次性消费，
   未布防/超时/通道缺失返回 False）；
3. `detach_network_session` 清理布防；`render_page`：attach 后布防，
   navigate 后 `wait_page_load(…, READY_TIMEOUT_SECONDS)` 再进
   `wait_page_ready`（此时 readyState 已 complete，首询即过）。
