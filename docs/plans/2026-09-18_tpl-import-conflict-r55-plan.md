# r55 批次计划：模板导入冲突条目级覆盖选择

日期：2026-09-16（分支创建于 main@b909a42f）
文件面：PromptTemplatesTab.tsx + 其测试；零后端改动。

## 背景

R32 的导入流程是"全有或全无"：skip 导入发现同名冲突后，window.confirm
询问"是否覆盖"，确认则把**全部**冲突条目覆盖重导，无法挑选。用户如果只想
覆盖其中 1 条、保留其余现有模板，做不到。

## 方案（纯前端）

冲突发生后不再 window.confirm，而是渲染一个内联选择面板：

- 列出全部冲突条目，各带勾选框（默认全选=全部覆盖）；
- 「覆盖选中项」→ 把信封过滤为选中条目，以 conflict=overwrite 二次导入
  （复用既有后端语义：覆盖保留现有 id，斜杠映射/变量记忆不断链）；
- 「保留现有」→ 丢弃面板，维持第一次 skip 导入的结果；
- 面板可在二次导入前随时取消。

复用既有 `promptApi.importTemplates(envelope, 'overwrite')` 签名不变——
过滤信封而非加参数，后端零改动、零风险。

## 测试（新增，此前导入流零覆盖）

- 冲突发生 → 面板出现且列出全部冲突名；
- 取消勾选 A、确认 → 第二次 importTemplates 收到仅含 B 的过滤信封 +
  conflict='overwrite'；
- 「保留现有」→ 不再发第二次调用，面板消失；
- 无冲突导入 → 单次调用，无面板。
