# UX-IA Round 2 · 批次 B：注入上下文统一预算

## 1. 目标
各注入块此前各自限额：项目资料按字符上限、记忆固定取 10 条、技能按条数省略，总量不受控。小窗口模型上，注入块会挤占历史，甚至让单轮请求直接超窗。本批次把它们纳入一个统一预算。

## 2. 规则
- 预算 = 有效窗口 × 0.35（下限 3000 tokens）。窗口未知时不处理。
- **只在超预算时生效**：按优先级从低到高截断——项目资料 → 记忆召回 → 技能清单 → 项目概览 → 项目约束 → SAGE.md。
- 截断方式是**尾部截断 + 说明**（`…[已按上下文预算截断约 N tokens]`），每块至少保留约 200 tokens（标题 + 开头），不整块丢弃。带闭合标签的块（技能清单）保留闭合标签。
- **永不截断**：基础系统提示词、环境信息、用户显式添加的附件。
- 块识别复用批次 A 的 `context_sources` 标记切分；截断效果会直接体现在 ContextMeter 的来源明细里。
- fail-safe：任何异常原样放行，不影响聊天。

## 3. 改动
- 新增 `backend/chat/context_budget.py`（`apply_context_budget` / `budget_for_window`）。
- `legacy_routes.py`：在有效窗口解析之后、预留位实测之前调用一次（+8 行，远低于基线）。截断后的 `system_content` 和 `dynamic_context_parts` 会参与后续的历史预算计算，所以截出来的空间会还给历史消息。

## 4. 测试
- `test_context_budget.py`（8 例）：未超预算不处理、按优先级逐级截断、基础提示词和环境不动、闭合标签保留、只有基础提示词超预算时不处理、异常输入、调用顺序（窗口解析 → 预算 → 预留位）。
- Python 3.11 / 3.8 均通过；`backend/tests/unit/chat` + `unit/api` 回归 613 例通过。
