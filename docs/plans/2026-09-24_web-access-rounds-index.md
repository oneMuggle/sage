## 3. 后续优化建议（按优先级）

1. ✅ **P3 事件驱动就绪等待**（已落地 R33 #1534/#1536）：`Page.loadEventFired` 替代 readyState 轮询
   （0.3s 粒度）——单次渲染约省 0.3-0.9s；事件通道基建已就位（R22/R23），
   需在 browser_events 增加 Page 事件按 sessionId 路由。
2. ✅ **P3 AB3 命中率细分到 host**（已落地 R34 #1541/#1544）：`tls_fingerprint.requests` 目前是全局
   计数；按域名聚合可与 per-host 出网指标对照，定位"哪些站点受益于指纹"。
3. ✅ **P3 渲染 e2e 冒烟**（已落地 R35 #1554/#1570）：真实站点（含 302 链 + 盾页 fixture）的渲染链
   e2e 用例，补单测 stub 与真实 CDP 行为之间的缝隙。
4. **P4 渲染池槽位自动调优**：按并发等待队列长度动态调整 render_pool_size
   （当前 1..4 手动配置，默认 2 已够用）。
5. **P4 win7 侧 curl_cffi 依赖评估**：curl_cffi 若发布 py3.8 兼容尾版本，
   可评估 win7 分支引入（当前明确排除）。
6. **P4 事件驱动懒加载** → 评估后推迟（R38）：站点懒加载实现高度异构
   （data-src 交换逻辑各站不同），IO 注入脚本难以通用；R37 快路径 +
   盲滚 + settle 组合已覆盖绝大多数场景，复杂度收益比不划算。

## 4. 遗留与备注

- `test_init_no_circular` 子进程超时已放宽（R28），如再现高负载抖动，
  优先考虑并发度而非继续加时间。
- 全量单测在本机偶发残留真实 chrome 进程（`sage_browser_*` 临时 profile）
  ——R26 修复树杀时序后待长期观察；如复发，排查对应用例的真实启动路径。
- 指标均为进程内存态（重启清零），定位为诊断视角而非审计（Round 15 口径）。

## 5. P4 收尾评估结论（R38）

- **IO 懒加载**：推迟，理由见 §3 第 6 条。
- **win7 侧 curl_cffi**：不适用——现行 curl_cffi 已放弃 Python 3.8 支持，
  win7 分支钉死 py3.8 依赖契约，不存在可安装的兼容尾版本；tls_transport
  为懒导入，win7 缺包时静态抓取自动回落标准 httpx（R27 设计），无需任何
  分支侧改动。
- **渲染池槽位自动调优**：推迟——render_pool_size（1..4 显式配置）已覆盖
  手动需求，R24 双槽 LRU 已消除并发瓶颈的主要形态；自动调优与显式配置
  语义冲突，待真实并发压力数据出现再议。
